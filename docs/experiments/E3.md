## Hypothesis

A standard pretrained baseline (MobileNetV2 or EfficientNetB0,
ImageNet weights, frozen base, new 38-class head) will match or beat
the custom CNN trained from scratch — or, if the custom CNN wins,
that is itself a reportable result for the paper.

## Dataset

- PlantVillage train split, 70,295 images, 38 classes; validation
  split, 17,572 images (same splits as retrain #2).
- Same pipeline for all three models: 128×128 RGB, pixels rescaled
  to [0, 1], augmentation (RandomFlip, RandomRotation 0.1,
  RandomZoom 0.1) on the training set only.

## Configuration

- 5 epochs per model, Adam lr 0.0001, batch 32, seed 42.
- Custom CNN: full architecture from `src/model.py`, trained from
  scratch (7,510,890 trainable params).
- Transfer models: frozen ImageNet base + GlobalAveragePooling2D +
  Dropout(0.3) + Dense(38, softmax) — 48,678 trainable params each
  (the head only).
- **Known limitation of this run (documented in the script before
  the run):** the bases expect ImageNet-style preprocessing
  (`preprocess_input`, inputs in [-1, 1]), but the shared pipeline
  feeds plain [0, 1] rescaling. The script's docstring already flags
  this as acceptable for a first comparison only.

## The EfficientNetB0 result is a failed run, not a comparison point

- 0.0273 is random chance for 38 classes (1/38 ≈ 0.0263), and
  val loss 3.6387 is ln(38) ≈ 3.6376 — the loss of a uniform random
  classifier. The model learned nothing in 5 epochs.
- Its trainable-param count (48,678) is identical to MobileNetV2's,
  so the head was trainable and the same size; the difference is in
  the frozen base or its inputs, not the head.
- **Do not quote 0.0273 as "EfficientNetB0's accuracy"** in any
  paper, slide, or the app. It measures a broken setup, not the
  architecture.

## Likely causes (hypotheses, not proven)

1. **Preprocessing mismatch + frozen BatchNorm (strongest).** The
   shared pipeline feeds [0, 1] inputs while the base expects
   [-1, 1]; with the base frozen, its BatchNorm layers normalise
   with ImageNet statistics that no longer match the shifted
   activations. EfficientNet (Swish activations, squeeze-and-
   excitation gates) is more sensitive to this shift than
   MobileNetV2 (ReLU6), which learned fine on the same inputs.
2. **Weight-loading problem.** If the ImageNet weights had failed
   to load, the base would be random — but a trained head on random
   features normally beats chance, so this alone does not explain
   exactly-chance performance.
3. A script bug specific to the EfficientNetB0 branch is unlikely:
   both transfer models are built by the same function with only
   the base class differing.

The cause cannot be settled from this run alone. The correct fix
is a focused re-run of EfficientNetB0 only, with each base's own
`preprocess_input`, plus a diagnostic that prints the pooled
feature statistics before training.

## Conclusions

- **At 5 epochs, the custom CNN beats the valid pretrained
  baseline:** 0.9239 vs MobileNetV2's 0.8884 — and the custom CNN
  at 10 epochs (retrain #2) reached 0.9421. The custom
  architecture is competitive; transfer learning did not win here.
- MobileNetV2 is the efficient baseline: 0.8884 with only 48,678
  trainable params (0.6% of the custom CNN's).
- The comparison is **incomplete as a three-way result** until
  EfficientNetB0 is re-run with the preprocessing fix. Until then,
  E3 is a two-model comparison plus one documented failed run.
