# E5 — Confidence Calibration & OOD Rejection

- **Date:** 7 November 2026
- **Script:** `src/calibrate.py` (run via `notebooks/calibrate_and_ood.ipynb`)
- **Artefacts:** `results/calibration.json`,
  `results/figures/reliability.png`, `results/figures/ood_roc.png`
  (logit `.npy` files are in `.gitignore` and were not committed)
- **Runtime:** Colab CPU, TF 2.21.0, no GPU. Calibration cell: 12 min 10 s.

## Hypothesis

1. The disease model's softmax outputs are overconfident in the
   usual way; a single temperature fitted on the validation set will
   reduce Expected Calibration Error (ECE).
2. An OOD score (max-softmax or energy) can separate real leaves from
   non-leaf photos well enough to replace the old, unmeasured 80%
   rule with a threshold chosen from an ROC curve.

## Dataset

- **In-distribution:** PlantVillage validation split, 17,572 images,
  38 classes (same split as the retrain #2 evaluation).
- **Out-of-distribution:** Caltech 101, plant categories excluded
  (bonsai, joshua-tree, lotus, strawberry, sunflower, water-lilly),
  760 images sampled from a pool of 8,830. (The E4 gate validation
  set was not present in this fresh runtime, so Caltech was sampled
  again with the same seed and exclusions.)

## Configuration

- Logits recovered from the saved model by re-applying the last
  Dense layer's weights with a linear activation; verified by
  self-check (max |softmax(logits) − model output| = 1.01e-06).
- Temperature fitted by minimising NLL of softmax(logits / T) on
  validation logits (scipy bounded optimisation).
- ECE: 15 equal-width bins on max probability.
- OOD signals compared: max-softmax (on calibrated outputs) and
  energy = −logsumexp(raw logits). Threshold: the highest value that
  still keeps ≥ 95% of real leaves above it (same convention as E4).

## Results

| Metric | Value |
|---|---|
| Temperature T | **1.0616** (NLL 0.1668) |
| Accuracy | **0.9421** (unchanged by calibration, as expected) |
| ECE before | 0.0077 |
| ECE after | **0.0042** |
| OOD ROC AUC, max-softmax | 0.8097 |
| OOD ROC AUC, energy | **0.8902** (chosen signal) |
| OOD threshold (energy, 95% TPR) | **6.0440** (on logsumexp of raw logits) |
| FPR at 95% TPR | 0.4487 |
| Validation leaves below threshold | 4.96% |
| OOD images above threshold (missed) | 44.87% |
| Old 80% rule: fraction flagged uncertain | 9.95% |
| Old 80% rule: flagged but actually correct | 6.06% of all validation images |

Reliability diagram (`results/figures/reliability.png`): both curves
track the diagonal; the calibrated curve is closer in the
high-confidence region where most images live (14,470 of 17,572 in
the top bin, accuracy 99.05% vs confidence 99.39% before, 99.19% vs
99.32% after). Low-confidence bins are noisy (3–459 images each).

## Before/after comparison (vs E1 baseline)

| Behaviour | Before (E1) | After (E5) |
|---|---|---|
| Confidence shown | Raw softmax, unmeasured | Temperature-calibrated (T = 1.0616), ECE 0.0042 |
| "Uncertain" rule | Unmeasured 80% confidence cutoff | Energy threshold 6.0440, chosen from the ROC curve |
| Validation images flagged uncertain | 9.95% (61% of them actually correct) | 4.96% |
| Non-leaf images caught by the score | Not measured (max-softmax AUC 0.8097) | 55.1% caught by the energy signal at 95% leaf retention |

## Limitations

1. **The model was already well calibrated.** T = 1.06 is close to
   1.0 and ECE was already 0.0077. Temperature scaling is a modest
   improvement (0.0077 → 0.0042), not a fix for a broken model — the
   honest finding is that calibration was never the main problem;
   the unmeasured 80% rule and the missing gate were.
2. **The OOD signal is only moderately good.** Energy AUC 0.8902
   beats max-softmax (0.8097), but at 95% leaf retention it still
   misses 44.87% of non-leaf images. It is a *second* layer of
   defence, not a replacement for the gate: the gate (E4) rejects
   99.87% of non-leaf images before the disease model ever runs,
   and the energy threshold then catches about half of the few that
   slip through.
3. OOD was measured on Caltech object photos only — no faces,
   screenshots or field photos in this set.
4. The threshold keeps 95% of *validation* leaves; real-world field
   photos may fall below it more often (unmeasured — needs the
   RW-Field set from Phase 4).

## Incident during the run

`src/calibrate.py` failed twice in `build_logit_model` with
`AttributeError: The layer sequential_1 has never been called and
thus has no defined input.` A model loaded from disk has no defined
`model.input` in Keras 3 (TF 2.21.0), and an eager dummy forward pass
does not create one. The fix — use `model.layers[0].input` as the
model input — was applied to the runtime copy only, verified by the
script's self-check (max diff 1.01e-06), and **has since been applied
to the repo script** so a fresh run works. (Same Keras 3 pattern as
the Grad-CAM fix earlier in this project.)

The run also could not connect at first ("Too many sessions") because
the finished E4 runtime still held a session; it was terminated after
confirming E4's artefacts were all recovered and committed.

## Conclusions

- Ship the temperature (1.0616): small, measured, honest improvement.
- Ship the energy threshold (6.0440) as the uncertainty rule: it
  flags half as many real leaves as the old 80% rule (4.96% vs
  9.95%) while adding a measured OOD catch (55.1%).
- Do **not** present the energy threshold as a non-leaf detector on
  its own: with 44.87% of OOD missed, the gate remains the primary
  defence, and the paper must report the FPR plainly.
- Accuracy is unchanged (0.9421) — calibration never changes the
  predicted class, only the confidence attached to it.
